# ai-macos

Канонический источник — checkout `ai-macos` внутри `repozitarium` на текущем
Mac. Точный путь брать из правил пользователя и текущего репозитория;
не переносить имя домашнего каталога с другой машины.
Для операций с компьютером использовать только прямые `mcp__ai_macos__*`.

## Подключение и версии

1. Перед первой операцией вызвать `system_health` и проверить
   `machine.matchesExpected === true`.
2. Использовать только инструменты и схемы, объявленные в текущей задаче.
   Файл навыка не подключает MCP, обновление исходников не заменяет загруженный
   сервер, а `native.state: compatible` не подтверждает готовность всех операций.
3. Если health содержит `runtime.buildId`, следовать
   [контракту runtime](references/runtime.md). Каталог зависит от реальных
   capabilities; отсутствие нужного метода означает недоступную возможность.
   Если объявлены `get_state` и `observe`, использовать короткие `targetId`
   и `elementId`; внутренние refs и параметры операций создаёт runtime.
4. Пока подключён старый MCP 0.3.x, читать
   [справку старого подключения](references/api.md). Не передавать новые refs
   старой схеме и не объявлять старый процесс обновлённым по версии исходников.

При отсутствии нужного прямого инструмента сообщить его имя и состояние
подключения. Deprecated `ai-macos-local`, REST, AppleScript, Computer Use,
AppShot, `screencapture` и shell-ввод не являются обходом отсутствующего MCP.
Для Storybook сохраняется отдельный специализированный MCP workflow.

## Рабочий цикл

- Сначала найти точную цель. Не считать пустой список видимых окон доказательством
  отсутствия скрытого окна или окна другого процесса. Проверять completeness,
  permissions, process identity и состояние окна.
- Перед pointer/keyboard input выполнить `check_input`, если он объявлен,
  иначе доступный `input_readiness`, после проверки машины.
  Продолжать только при подтверждённой готовности ввода.
  Пассивный health и готовность clipboard этого не заменяют.
- Перед каждым снимком одним предложением сформулировать ожидаемое изображение
  и передать его в `caption`. По умолчанию выбирать medium detail, если схема
  его поддерживает. Сравнить полученное изображение с ожиданием перед вводом.
- Готовность изображения подтверждает безопасное чтение кадра, но не готовность
  ввода: point-действие всё равно требует отдельный свежий Native hit proof.
- Координаты брать из свежего observation и только в его объявленной системе.
  Window-local координаты старого MCP и image coordinates runtime не взаимозаменяемы.
- После действия проверить actual result и новый снимок, когда важен визуальный
  эффект. Доставка события не доказывает, что приложение выполнило задачу.
- В коротком native API наблюдение разрешает одно действие. Перед следующим
  действием получить новое `observe`; status/cancel нового наблюдения не требуют.
- Не повторять действие при timeout или неизвестном исходе. Сначала получить
  operation status; подтверждение запроса отмены ещё не означает stopped/cleanup.

## Окна и диалоги

В runtime выбирать refs из inventory. PID, title, geometry и CGWindowID —
наблюдения; новое окно или новый процесс не наследуют прежнюю identity.
Скрытое AX-окно может быть пригодно для адресованного show без CG mapping;
снимок требует собственного подтверждения доступности захвата.

Sheet — отдельная цель с подтверждённым owner. Не подменять focused sheet
родительским окном, не выводить принадлежность из пересечения прямоугольников
и не выбирать похожее окно при stale ref. При появлении Save/Open снова получить
inventory, выбрать точную surface и наблюдать её доступным способом.

В старом MCP предпочитать точный `{app, pid, windowId}` из свежего списка,
когда это поддерживает схема. При ошибке exact ID не переходить на title/index.
Не передавать диагностический index 0 как обычное окно.

## Clipboard и разрешения

Clipboard читать только по явной просьбе пользователя. Применять отдельные
clipboard tools; типизированный текст после записи проверять в приложении,
если пользователь поручил вставку. Не считать text-only восстановление
полным восстановлением всех форматов pasteboard.

При запуске установленного runtime включён согласованный режим запроса
недостающих прав: Accessibility, Screen Recording, Post Events и Input
Monitoring. Официальные AX/CG request API вызывает сам long-lived helper,
один раз для отсутствующих прав. Пользователь подтверждает доступ в macOS;
вызов request API не означает, что право уже выдано или диалог появился.

Пока `startup.permissions` сообщает ожидание, зависимые операции недоступны.
`system_health` остаётся пассивным и не повторяет запросы. При отказе сообщить
точный helper path и состояние; не запускать ввод или новые циклы запросов.
Вне этого startup-потока открывать настройки и повторно запрашивать права можно
по явной просьбе пользователя.

## Обновление и диагностика

При поручении обновить или исправить ai-macos сначала полностью прочитать
репозиторный `AGENTS.md`. Проверить Git, изменённые dependencies и путь навыка.
Если изменился lockfile, обновить workspace links через
`bun install --frozen-lockfile`. Symlink на `skills/ai-macos` копировать не нужно.

Диагностика может проверить MCP initialize/tools/list и пассивный health с
конфигурацией клиента. Это не разрешает desktop-действия через отдельный
диагностический клиент и не доказывает появление инструментов в текущей задаче.
Installed build и live результат проверяются отдельно от source tests.

[Журнал инцидентов](references/incidents.md) содержит исторические случаи:
проверять применимость к загруженной версии, различать наблюдение и гипотезу,
не превращать старый обход в разрешение нарушить текущую identity или ownership.
