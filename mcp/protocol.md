# Протокол zavx0z

Единственный публичный инструмент `zavx0z` объявляет три необязательных поля:

| Поле | Назначение |
| --- | --- |
| `node` | Раздел: `root`, `computer` или `computer/<операция>`. По умолчанию `root`. |
| `action` | Явное выполнение операции из текущего каталога раздела. |
| `input` | Объект аргументов по динамическому контракту операции; по умолчанию `{}`. |

Последовательность вызовов:

1. `{}` — корневая справка; не требует доступного Runtime.
2. `{"node":"computer"}` — текущие доступные операции.
3. `{"node":"computer/system_health"}` — контракт, без выполнения.
4. `{"node":"computer","action":"system_health","input":{}}` — выполнить проверку машины.

Продолжать управление можно только после `machine.matchesExpected=true`.
Для следующей операции сначала получить её контракт, затем передать аргументы
в `input`. Для ввода требуются `check_input` и свежее `observe` по контрактам
Runtime. После неизвестного исхода не повторять действие: запросить его статус.

Без `action` даже непустой `input` не запускает операцию. Справка и успешное
подключение не доказывают выполнение. Результат операции возвращается из Runtime.

Внешняя схема и схема в корневой справке строятся из одного определения.
Каталог операций, их доступность и параметры остаются динамическими.
После обновления прокси клиенту необходимо заново получить `tools/list`;
уже закэшированная пустая схема не обновляется от чтения справки.
