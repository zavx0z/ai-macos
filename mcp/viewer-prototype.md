# Codex App — общее приложение беседы

Статус: прототип. Локальные тесты не доказывают сохранение iframe в ChatGPT.
Runtime и Native не изменяются; обновляется только отдельный proxy.

## Инструменты

- `zavx0z` — команды и динамическая справка **без** UI-шаблона.
- `codex_app {}` — один вызов открытия общего приложения беседы.
- `codex_app_next` — приватный app-only инструмент чтения/ожидания;
  UI-шаблон к нему не привязан. Не является командой открытия нового окна.

Приложение запускает `ui/initialize`, объявляет inline/fullscreen/pip и принимает
результат открытия. Кнопки «На весь экран», «Поверх чата» и «В чате» запрашивают fullscreen, PiP
и inline соответственно. Фактический mode берётся из ответа хоста: запрос
не гарантирует переход. Переключение не вызывает opener повторно.

## Первое открытие

Первый ответ `zavx0z` в беседе содержит `structuredContent.codexApp` со статусом
`CODEX_APP_OPEN_REQUIRED` и дублирующую текстовую подсказку:
модель должна вызвать `codex_app {}` один раз и продолжить задачу, **не повторяя
предыдущую команду**. Обычные команды не имеют UI-шаблона, поэтому сами
не создают карточки. Поля результата Runtime сохраняются рядом с дополнительным `codexApp`;
во всех последующих ответах это поле отсутствует. Это подсказка модели,
а не принудительное открытие iframe
сервером: её выполнение зависит от ChatGPT. Fullscreen/PiP выбирает пользователь.

Подсказка выдаётся один раз в пределах живого состояния беседы. Явное открытие
заранее подавляет её; после закрытия приложения автоматического повторного
открытия нет. При перезапуске proxy или удалении неактивного состояния флаг
теряется. «Один раз навсегда» без постоянного хранилища не гарантируется.
`openRequested` означает вызов opener, а `mountId` — подключившийся виджет.

Публичное имя UI и инструмента — Codex App / `codex_app`. Установленный плагин
«zavx0z» сохраняет identity. Старые имена инструментов принимаются как aliases
для уже открытых карточек, но не публикуются в новом каталоге.

## Данные

`_meta["openai/session"]` вместе с subject/organization разделяет беседы.
Если хост не передал session, открытие возвращает `VIEWER_SCOPE_UNAVAILABLE`;
общего запасного просмотра для всех пользователей нет. Эти метаданные служат
корреляции, а не заменяют аутентификацию существующего подключения.

Каждой беседе соответствует отдельный viewer ID и случайный read token.
Token передаётся только в `_meta` результата открытия. Виджет использует его
для чтения, но модель не получает token в structuredContent. В памяти —
не больше восьми бесед, по одному последнему содержимому до 4 MiB.
Неактивная беседа без ожидающего запроса удаляется при следующем обращении
после 30 минут. Снимки не сохраняются на диск.

Сервис computer сохраняет последний снимок своей беседы даже до открытия
приложения. Opener передаёт его сразу; следующие снимки заменяют содержимое
того же элемента img. Подпись показывается под снимком, displayedVersion
подтверждается только после декодирования изображения. Модель продолжает
получать ImageContent независимо от UI.
Демонстрационные источники `demo-a`/`demo-b` публикуют текст. Health и справка
ничего не публикуют и не меняют показанные данные. Запоздавший ответ старого запроса не
заменяет более новую публикацию.

## Снимки только после команды агента

Ни UI, ни таймер ожидания не вызывают observe/capture. Захват выполняет Runtime
по явной команде агента. Только результат команды с изображением публикует
новую ревизию; timeout возвращает changed=false без повторного снимка и без
перерисовки изображения. Команда без изображения оставляет последний снимок.

## Ожидающий запрос через существующий туннель

Виджет держит один `codex_app_next(after=version, waitMs=10000)`.
Сервер отвечает при новой ревизии или по окончании ограниченного ожидания.
После ответа виджет обновляет содержимое того же mount и снова ждёт.
Это **long polling через MCP**, не WebSocket и не доказанная потоковая
поддержка Secure MCP Tunnel. Секундного опроса нет, но по истечении 10 секунд
ожидающий запрос переоткрывается. При сетевом timeout приложение переподключает только чтение с паузой
2–30 секунд, сохраняя mount и последнюю ревизию. Кнопка ↻ ускоряет
переподключение. Capture/observe при этом не вызываются. Ошибка формата,
декодирования или истёкшая серверная session останавливают цикл.

Одновременно разрешён один ожидающий запрос и один mount ID на просмотр.
Второй mount отвергается. Это защищает backend от конкурирующих readers,
но не запрещает самому ChatGPT создать новую карточку при повторном вызове
инструмента открытия. Поэтому opener вызывается один раз. Teardown/pagehide
освобождают mount по возможности; неожиданное закрытие хоста может потребовать
новой сессии/восстановления, а не автоматического захвата чужого mount.

## Приёмка в ChatGPT

1. Обновить инструменты существующего подключения, если новый opener не виден.
2. Вызвать `zavx0z {}`: `viewer.scopeAvailable` должен быть true.
3. Вызвать `codex_app {}` один раз, нажать «На весь экран».
4. Через `zavx0z` вызвать:

```json
{"node":"viewer","action":"publish_demo","input":{"service":"demo-a","text":"Первый сервис"}}
```

Затем повторить с `demo-b` и другим текстом. Оба результата должны появиться
в том же открытом приложении без новых UI-карточек.

5. Вызвать `{"node":"viewer","action":"status"}`: прежний mountId,
   увеличенные version/displayedVersion, displayMode=fullscreen.
6. Проверить PiP и возврат в inline: содержимое и mountId должны сохраниться.
   Получить настоящий скриншот через computer/observe и убедиться, что снимок
   виден в приложении. Отдельно проверить снимок первой командой до открытия.
7. Вызвать справку и system_health: содержимое приложения не должно измениться.
8. Проверить работу после двух 10-секундных периодов ожидания и остановку при
   ошибке связи. Статус backend ссылается на сведения, присланные виджетом;
   факт отсутствия новых карточек подтверждается глазами пользователя.

Диагностический `viewer/wait` позволяет проверить отложенный ответ и
параллельную публикацию через MCP без UI и без реального ввода на Mac.

Основание: [OpenAI UI](https://developers.openai.com/plugins/build/chatgpt-ui),
[метаданные беседы](https://developers.openai.com/plugins/reference#_meta-fields-the-client-provides),
[MCP Apps](https://github.com/modelcontextprotocol/ext-apps/blob/main/specification/2026-01-26/apps.mdx).

Это подтверждает режимы и доставку текста, но не приёмку захвата экрана.

Попытка одного снимка основного дисплея через ChatGPT завершилась

`operation:e2d27f56-e343-4c59-991a-cf3958394695` не повторялась автоматически.
Показ PNG проверен локально через изолированный Runtime и декодирование UI;
живой снимок дисплея пока заблокирован отдельно от приложения.

Первоначальная текстовая подсказка открытия не дошла до модели в живом
ответе, хотя сервер отметил autoOpenSuggested. Поэтому сигнал открытия
добавлен также в structuredContent.codexApp. На установленной сборке
`3b78365` ChatGPT получил этот статус, вызвал codex_app один раз и опубликовал
demo-b. В приложении виден текст «Автооткрытие Codex App после команды»;
перевод в PiP сохранил его.

После перезапуска proxy новая серверная сессия получила новый viewerId.
В истории осталась карточка предыдущей сессии: в DOM обнаружены два iframe
с одним URI, относящиеся к двум разным открытиям до/после обновления.
Поэтому гарантия одного активного mount действует внутри живого состояния
proxy, а не как удаление исторических карточек или сохранение iframe
через перезапуск backend.

## Компактный просмотр снимков

Область содержимого имеет пропорции 16:9; панель кнопок занимает отдельные
44 px сверху. Изображение вписывается целиком через object-fit: contain,
без обрезки, растягивания и внутреннего скролла. В fullscreen/PiP ширина
ограничена также доступной высотой хоста. ResizeObserver сообщает высоту
ChatGPT при изменении размера; снимки и сетевые команды он не вызывает.

Native observe для дисплея, всего рабочего стола и окна запрашивает уменьшенный
PNG с включённым системным курсором: не более половины исходного разрешения и не более 1280×720, с сохранением
пропорций. Scale вычисляется до захвата по подтверждённой геометрии и backing
scale. Это ограничение короткого native API; низкоуровневые capture contracts
продолжают принимать явно заданные budgets. Захват и обновление изображения
по-прежнему выполняются только в результате команды агента.

### Проверка уменьшенного кадра и размеров

На Runtime `runtime-284eddee211e125927249ede` ChatGPT получил настоящий
снимок основного дисплея 960×600 с complete=true и errors=[]. В Codex App
подтверждены naturalWidth=960, naturalHeight=600, область 640×360 и панель
44 px. scrollWidth/clientWidth=640, scrollHeight/clientHeight=404;
fullscreen и PiP сохраняют картинку. Размеры проверены по DOM и изображению.

Вторая команда создала кадр с version=2 и прежним mountId, но в UI осталась
ревизия 1 после `Request timeout`. Это выявило отдельный дефект восстановления
канала, исправленный в UI v3: сетевые ошибки повторяют только приватное чтение
после паузы, не захват. Максимальное серверное ожидание UI снижено до 10 секунд,
чтобы оставить запас на транспорт. Native observe теперь включает курсор.

### Готовность установщика на Intel Mac

При установке версии с курсором исправный passive doctor занял 2,30 секунды.
Прежний предел 2 секунды на процесс приводил к ложной ошибке readiness и
неподтверждённому откату. Установщик теперь даёт отдельному doctor до 10 секунд
внутри общего deadline 30 секунд; metadata helper — до 15 секунд. Условия
готовности и подписи не ослабляются. Пустой stderr больше не скрывает исходную
ошибку запуска/таймаута. Регрессия покрыта тестом ограниченного doctor budget.
