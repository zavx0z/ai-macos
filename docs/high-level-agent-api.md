# Удобный агентский API поверх runtime

## Решение и порядок работы

Владимир согласовал этот вариант 15 сентября 2026: сохранить runtime и точную
адресацию окон, добавить удобный внешний слой, отложить полный JavaScript REPL.
Проект проверен на четырёх сценариях из
[сравнения вариантов](computer-use-api-comparison.md).

Проект проверен на четырёх fixture-трассах:
[результаты и ограничения](reviews/high-level-api-scenarios.md).
Проверка подтверждает форму интерфейса; она не заменяет implementation или live
test. Source blocks приняты в `2798c3d`, `34f5394`, `cb97922`, `c31909a` и
`2be38e1`: target/element bindings, observation, target-scoped status/cancel,
короткие actions, AXPress и retained AX snapshot существуют в source.

Текущий статус: **source-only**. Production RuntimeHost/MCP catalog binding,
aggregate desktop P1 review, installed cutover и live matrix ещё не завершены.
Подключённый MCP остаётся 0.3.0; наличие source methods не означает, что текущая
задача Codex уже может их вызвать.
Внутренние window/browser/input/capture методы остаются исполнительной границей;
внешний слой не отправляет события в обход RuntimeCore.

## Выбор цели

`get_state({ kind?, app?, pid? })` возвращает краткий список доступных окон
и настроенных browser instances. Для окна видны `targetId`, приложение, PID,
заголовок и состояния hidden/minimized/visibility. Неизвестное состояние
показывается явно. `targetId` выдаётся сервером и принадлежит текущей задаче.

Список сразу выдаёт адресуемые цели: отдельный обязательный вызов bind не нужен.
При совпадающих именах Chrome агент выбирает по записи окна, а не угадывает PID.
Обновление списка сохраняет привязку к той же identity; закрытое окно не
заменяется новым с тем же заголовком.

Ответ также сохраняет `applications` с PID, `axStatus` и числом AX-окон,
а CG-only окна — в диагностическом `unavailableWindows` без ложного action ID.
Это различает отсутствующее приложение, процесс без окон и недоступный AX.
Наличие известного неуправляемого окна не означает неполную инвентаризацию.

`get_state` не резервирует все браузеры и не создаёт ADB forwards ради списка.
`get_tabs({ browserId })` подключает только выбранный настроенный instance через
существующий lifetime coordinator и возвращает вкладки с `targetId`, исходным
CDP target ID, профилем, заголовком и URL. URL не становится идентификатором.

## Операции

| Метод | Минимальные аргументы | Поведение |
| --- | --- | --- |
| `observe` | `targetId`, `mode: ax/screenshot/both`, `caption` для снимка | Возвращает состояние/снимок выбранной цели |
| `show_window` | `targetId` | Показывает точное существующее окно и возвращает его новое AX-состояние |
| `click` | `targetId`, `elementId` либо `[x,y]` | AX-действие или клик по точке ранее выданного снимка |
| `type_text` | `targetId`, `text` | Вводит текст в подтверждённую цель |
| `press_key` | `targetId`, `key`, `modifiers?` | Выполняет проверенную клавишу/сочетание |
| `scroll` | `targetId`, anchor, direction, amount | Прокручивает с явно определённой единицей |
| `drag` | `targetId`, from, to | Перетаскивает в системе координат снимка |
| `get_target_status` | `targetId` | Показывает незавершённые операции и последний результат |
| `cancel_target` | `targetId` | Отменяет только операции этой задачи для этой цели и сообщает cleanup |

Названия и точный формат полей фиксируются после проверки сценариев. В частности,
для AX предпочтительна короткая opaque `elementId`, связанная с последним
snapshot; копирование изменяемого числового индекса Codex не является целью.
Пиксели `click`/`drag` относятся к выданному снимку, не к глобальному экрану.
Для снимка агент передаёт ожидаемое изображение в `caption`; слой сохраняет
его без подмены. Сочетание задаётся отдельными полями, например
`{ "key": "l", "modifiers": ["cmd"] }`, по существующему macOS key grammar.

## Что скрыто от агента

Слой хранит настоящие refs приложения, окна или вкладки, inventory revision,
последний AX snapshot, observation/frame и внутренние clientRequestId. Runtime
по-прежнему выдаёт leases, fences, evidence и проверяет native результат.
Агент не конструирует эти объекты самостоятельно.

Изменение текста AX не должно автоматически менять личность окна. Изменение
геометрии, закрытие окна, смена native/runtime generation или истечение
наблюдения выдаёт понятное требование заново получить состояние. Новый кадр
не подставляется под старые координаты молча.

## Наблюдение и следующее действие

Рабочий цикл native-цели: `observe` → одно действие → новое `observe`.
`show_window` также может выдать новое наблюдение после показа точного окна.
Принятое действие расходует наблюдение; отдельное следующее действие требует
нового. Ввод целого текста, последовательность клавиш и drag остаются одной
операцией со своей проверкой вмешательства во время исполнения.

Перенос доверия между отдельными keyboard-операциями не входит в этот контракт.
Это позволяет не сохранять цепочки предыдущих synthetic events и не считать
изменившийся интерфейс прежним. Чтение статуса и отмена сохраняются независимо
от пригодности наблюдения для нового ввода.

Сохранённые пиксели имеют ограниченный срок жизни до 120 секунд. Перед кликом
runtime отдельно подтверждает текущие identity, geometry, focus и topology;
новый point proof действует не более 5 секунд. Это проверка координаты в том
же окне, а не доказательство неизменности нарисованной кнопки. Действие по
AX-элементу использует его собственную snapshot-bound identity.

## Долгие действия и потерянный ответ

Каждый принятый вызов связывается с целью до ожидания backend; queued и admitted
операции учитываются отдельно. `cancel_target` работает, пока исходный вызов
ещё выполняется, и не требует ID, который агент получил бы лишь в конце.

Успешное действие возвращает короткий результат и `operationId`. При потере
ответа агент читает `get_target_status`; слой не повторяет мутацию автоматически.
Отмена до dispatch, подтверждённый cleanup и неизвестный outcome различаются.
Права на чтение результата/cleanup не исчезают только потому, что окно закрыто
или срок обычных действий по его binding истёк.

Bindings разделены по authenticated client lineage. Отмена одной задачи не
останавливает ввод другой. При смене runtime generation старый handle не
перепривязывается к похожему окну.

## Проверки перед реализацией

1. Скрытый Chrome: выбрать точную запись окна, показать существующее окно,
   проверить новое состояние; запуск нового Chrome отсутствует в трассе.
2. Одинаковые URL: выбрать instance/profile, затем точный CDP target;
   передача вкладки в другой профиль должна быть отвергнута.
3. AX-действие: element handle действует только в выданном snapshot;
   настоящее AXPress не заменяется кликом в центр прямоугольника.
4. Отмена ввода: отменить queued и уже начатую операцию, сохранить outcome и
   ownership cleanup, не повторить событие после потерянного ответа.

Счётчики вызовов и JSON-объёмов относятся к проверенным fixture-трассам.
Время, токены модели и live-успешность требуют отдельного измерения. Отсутствующий
AX/backend метод фиксируется как необходимая реализация, а не как успешный
сценарий или скрытая подмена поведения.
