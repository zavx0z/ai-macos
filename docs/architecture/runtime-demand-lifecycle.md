# Runtime без фонового опроса рабочего стола

## Простой и операции

Простой пользователя не является ошибкой Runtime. Смена focus остаётся событием,
которое может инвалидировать старое наблюдение, но не завершает helper и не
запускает AX-подписку к очередному приложению только из-за его активации.
AX-подписка на текущий foreground уточняется при запросе coverage. Старое приложение
отписывается при таком уточнении. Пока существующая подписка нужна наблюдению,
системные AX/Workspace/EventTap callbacks продолжают приходить: это не polling.

Проверка permissions/tap и продвижение `coveredThrough` выполняются в main-runloop
barrier запроса coverage, без NSTimer каждые 250 мс. Native PUSH пробуждается
через coalescing DATA_OR notification, а не таймером 20 мс. Тот же notifier сообщает
об отказе coverage; gap не теряется при отсутствии пользовательского ввода.
Main runloop ждёт события и пробуждается для exit, без цикла с паузой 20 мс.

Runtime heartbeat включён только пока Core имеет незавершённые Native operations.
После завершения отменяется текущий запрос и удаляется его timer; поздний отказ
не переводит простой в quarantine. Потеря контроллера во время исполнения по-прежнему
останавливает Native job. Transport EOF и ошибки framing не превращаются в ready.

Watchdog транспорта вооружается одноразово только для неполного пакета или ожидающей
записи. Пустой исправный канал не проверяется каждые 100 мс.

## Результат захвата

`capture.start` вызывается один раз. Следующий `result(waitForCompletion: true)`
ждёт NSCondition, которую сигнализирует capture callback; запросы каждые 10 мс
отсутствуют. Это ожидание вынесено из action queue, поэтому cancel/status остаются
обрабатываемыми. Оно имеет тот же абсолютный срок capture operation с резервом
остановки. Nonblocking result сохранён для explicit status/cleanup и совместимости.
Pending после исчерпания срока не выдаётся за завершённый кадр.

## Срок операции

Внешний метод задаёт absolute deadline. Вложенные внутренние методы наследуют его
через локальную привязку к AbortSignal, не заводят независимые method timers и не
начинают новый полный budget. Обёртка tracked action сохраняет deadline при создании
дочернего сигнала отмены. Core ограничивает intent этим deadline; более короткий
явный срок клиента сохраняется. Внутренние operation builders используют тот же срок.

Сроки отдельного системного вызова и расписания ввода могут быть короче: они не
расширяют deadline операции. Cleanup после отмены имеет отдельный ограниченный
резерв. Timeout мутации не доказывает отсутствия эффекта, поэтому replay запрещён.
Неподтверждённая durable запись по-прежнему блокирует зависимый execution: это не
ошибка observer и не основание выдумать успешный commit/cleanup.

## Handles и views

У target/element handles больше нет стандартного 60-секундного action TTL.
У view нет стандартного 30-секундного TTL. `actionExpiresAt`/ticket `expiresAt`
публикуются только при явно настроенном ограничении. Точное существование цели,
generation, native snapshot и изменение GUI проверяются независимо от возраста ID.
Одноразовый Native admission proof ограничен deadline текущей операции, не временем
создания исходного снимка. Опциональный строгий maxCoverageLag остаётся политикой,
а не дополнительным стандартным секундным watchdog.

Неограниченного хранения нет: counts/bytes ограничены; новый AX snapshot заменяет
старые elements, закрытые/invalidated handles имеют control retention; после
подтверждённого завершения клиентской lineage handles удаляются. Незавершённые
операции удерживают control evidence независимо от возраста.

Сохранение ID не означает, что изображение неизменно. Физический ввод, неизвестная
цель события, lifecycle и смена focus могут инвалидировать все зависимые views.
Известные window-structure events проверяются по exact target. Эта консервативная
проверка не объявляет Runtime неисправным и не имитирует знание всех изменений UI.
Ограничения хранения исходных кадров и Native AX snapshots не отменены.

## Остальная фоновая работа

Каталог проверяется по ETag только при явном запросе. Callback подписчика сообщает
об изменении, обнаруженном этим чтением; сам callback сеть не запускает.
PiP обновляется из tool-result/globals и одним initial fetch. Для хоста, который
не доставляет обновления старому виджету, есть ручной Refresh; секундного polling нет.

Client expiry использует один timer ближайшего истечения, перепланируемый при
изменении session registry. Периодического секундного sweep нет. Авторизация и её
продление сохранены и не служат доказательством актуальности окна.

Ротация проверяется после изменения activity/capabilities и завершения вызова, а не
каждую секунду. Убрана ротация просто по возрасту процесса (23/24 часа). Замена по
действительному отказу и приближению к ограничению registry сохранена: удалять её,
сохраняя накопительные request/frame refs, означало бы скрыть исчерпание ресурсов.

Dev hot reload, отдельный opt-in Chrome CDP monitor, ожидания загрузки страницы,
авторизация, установка, shutdown и подтверждение освобождения ввода не удалены.
Они не объявляются условиями отсутствия человеческой активности.

## Проверка перед установкой

Изменения Runtime и Native устанавливаются одной согласованной сборкой. CI выполняет
Bun Runtime/Native/Screen/Input tests, TypeScript и C/Objective-C fixtures без реального
ввода. Проверка на пользовательском Mac и установка выполняются отдельным этапом.
