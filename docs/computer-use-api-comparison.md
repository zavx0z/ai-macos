# Выбор агентского API

Дата: 15 сентября 2026. Переход на Codex CUA приостановлен до выбора варианта.
Проверенный внешний контракт и его источники: [Computer Use API](computer-use-api.md).

## Вывод ведущего

На текущем этапе полная совместимость с Codex CUA не оправдана. Рекомендуется
сохранить наш runtime и добавить удобный внешний слой для приложения, точного
окна и вкладки, скрывающий служебные параметры. Это рекомендация по результатам
анализа, а не поручение продолжать остановленную миграцию.

## Варианты

| Вариант | Польза | Цена и ограничения |
| --- | --- | --- |
| Оставить текущий подробный MCP API | Минимальные новые изменения; явные capabilities и operation receipts | Агент переносит refs, revisions, evidence и request IDs; простой сценарий требует знания внутренних контрактов |
| Удобный слой над нашим MCP | Короткие действия и сохранённая привязка к окну/вкладке; служебные данные остаются внутри | Нужны управление привязками, обновление наблюдений и сквозные тесты; JavaScript-синтаксис Codex не воспроизводится полностью |
| Полная совместимость с `cua` и `cua_repl` | Перенос JS-сценариев; переменные и объекты между вызовами; зависимые действия можно объединять в программу | Дополнительная среда выполнения, её lifetime/reset/timeout, RPC для изображений и отмены, изоляция задач и большая матрица совместимости |

## Что полезно перенять

1. Связанный объект цели: агент выбирает приложение/окно/вкладку один раз,
   а следующие действия используют сохранённую точную identity.
2. Начальное AX-состояние при выборе цели; явные операции полного состояния,
   изменений дерева и снимка. Автоматический вывод уменьшает ручную сборку ответа.
3. Короткие глаголы `click`, `typeText`, `pressKey`, `scroll` и единый принцип
   работы с native apps и browser targets.
4. Внутренняя генерация operation IDs, scopes, leases и preconditions.
5. Отдельные ошибки inventory приложений и браузеров: частичная недоступность
   одного провайдера не должна скрывать остальные.

Эти преимущества не требуют копирования приватного сервиса OpenAI или запуска
произвольного JavaScript внутри нашего MCP.

## Где полное совпадение мешает или увеличивает объём

- **Окна и Chrome-профили.** У внешнего `App` Codex нет явных PID/window ID.
  Для исходного инцидента ai-macos необходимо выбирать существующее окно среди
  одноимённых процессов и различать скрытое, свёрнутое и отсутствующее окно.
  Эта возможность должна оставаться доступной, даже если большинство действий
  используют короткую привязку.
- **Координаты.** Codex принимает пиксели снимка окна без явного receipt.
  Наш слой может скрыть receipt, но обязан сохранить тот же кадр и его
  преобразование. Пять секунд текущей frame/target freshness непригодны для
  обычного рассуждения агента; это самостоятельный вопрос usability, который
  не решается переименованием методов или слепым увеличением всех TTL.
- **AX и paste.** Indexed AXPress, setValue, selectText, secondary actions,
  formatted paste и условное восстановление всех clipboard formats — реальные
  возможности backend. Часть их полезна независимо от выбора API, но одни
  объявления методов не реализуют их.
- **Browser host.** `markDeliverable`, `markHandoff`, claiming пользовательских
  вкладок и некоторые параметры видимости относятся к окружению Codex.
  Обычный CDP не предоставляет эквивалент каждого такого действия.
- **JS-сессия.** Постоянный REPL добавляет состояние переменных, зависшие
  программы, сброс, двоичную передачу изображений и отдельную отмену запросов.
  Обрыв REPL не подтверждает native cleanup. MCP-клиенты разных задач должны
  иметь отдельные bindings и reset authority.
- **Наблюдаемость.** Подробные MCP tools явно объявляют read/mutation и
  capabilities. Единый `js` скрывает это от внешнего клиента; внутренний
  диспетчер должен сохранить различение операций.
- **Сопровождение.** Проверен локальный snapshot `@oai/cua` 0.2.4. Это не
  подтверждение публичной гарантии стабильности внутренних схем Codex.
  Нельзя превращать установленный пакет OpenAI в обязательную runtime dependency.
- **Предел проверки.** В текущей конфигурации native CUA отключён; пакет
  содержит его типы и реализацию JS-клиента. Сравнения live-поведения двух native
  backend на этом Mac пока нет. Совпадение API не добавит background/locked use.

## Что измерить до следующего решения

Сравнить нынешний API и небольшой вариант удобного слоя на одинаковых задачах:

1. Найти и показать существующее скрытое окно Chrome при нескольких процессах.
2. Выбрать нужную вкладку среди одинаковых URL в разных профилях.
3. Прочитать AX, выполнить действие и проверить новое состояние.
4. Прервать ввод и проверить отсутствие повтора либо потерянного cleanup.

Фиксировать правильность выбранной цели, число обращений модели к инструментам,
объём передаваемых служебных данных, фактическое время и восстановление после
ошибки. Сокращение видимых вызовов не означает сокращения внутренних проверок.
Экономия токенов, времени и рост успешности пока не измерены.

Если удобный слой даёт нужное улучшение, полный REPL не нужен для выпуска.
Если затем появятся реальные программы с зависимыми циклами, которые плохо
выражаются через MCP, можно отдельно рассмотреть совместимый JS-клиент.
